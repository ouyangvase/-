# Project 12 baseline and root-cause record · 2026-08-23

## Observed baseline

The existing demo could render and send room chat messages, but the transport did not have one authoritative ordering cursor. History was timestamp-oriented, while SSE, realtime and refresh paths deduplicated primarily by message id. This left two failure cases:

1. two messages created in the same time unit could be ordered differently between history and realtime;
2. reconnecting or loading older history could append an already-seen message or skip a message between cursors.

The room shortcut buttons also opened UI affordances without server-backed leaderboard/reward reads, and the operations console contained static fallback panels for several operational views.

## Root causes

- `room_messages` had no monotonic per-room sequence.
- The client had no shared merge key across initial history, SSE, Supabase Realtime and polling.
- The worker outbox payload did not carry the persisted chat message ordering data.
- The leaderboard and reward panels were not consistently connected to room/admin APIs.
- Jobs and immutable rule versions were not visible in the admin navigation.

## Exit criteria used for this pass

- Sequence is assigned server-side and is unique within a room.
- History supports both older-page (`before`) and reconnect (`after`) cursors.
- Client merge is idempotent across all transport paths.
- Worker-created internal notices preserve the same sequence metadata.
- Reward claiming has an idempotent endpoint and a refresh path.
- Admin can inspect overview, current room, ledger, audit, jobs/outbox and active rules.
- Tests prove ordered chat history and an empty replay after the latest cursor.
