# Telegram Bot + Mini App setup

This repository contains a safe Bot service. In local Demo mode it exposes `/health` and `/telegram/webhook` without sending; with an operator-supplied token it configures commands/Menu Button, registers the webhook and sends validated `/start` responses through the Telegram Bot API.

## BotFather checklist

1. Create a bot in BotFather and keep the token in a secret manager only.
2. Set the display name, username and description from the central brand configuration.
3. Set the Mini App domain to the HTTPS Vercel origin. The origin must be HTTPS; do not use the local Vite URL in Telegram.
4. Set the Bot Menu Button to `进入游戏大厅` and use the same Mini App URL. The inline/reply Web App button is generated by `buildReplyKeyboard()`.
5. `/newapp` is optional. Use it only if you also need BotFather's standalone Web App/attachment entry; it is not required for the `/start` → `进入游戏大厅` flow.
6. Set these commands: `/start`, `/play`, `/wallet`, `/history`, `/missions`, `/referral`, `/rules`, `/support`. The descriptions are centralized in `apps/bot/src/bot.ts`.
7. Apply `infra/schema.sql` and migrations `002` through `006` to Supabase before switching the API to staging; migration `006` makes internal packet claims durable across Vercel instances.
8. Set `TELEGRAM_WEBHOOK_URL` to `https://<vercel-origin>/api/telegram/webhook`, then run `pnpm telegram:configure` with the token, URL and secret in the server environment.
9. Test `/start`, `/start ref_<code>`, the Web App button, Menu Button, back navigation and server-side `initData` verification.

The local service contract is implemented in `apps/bot/src/bot.ts`: `buildWelcomeMessage()`, `handleTelegramUpdate()`, `GET /health` and `POST /telegram/webhook`. Production Vercel exposes `POST /api/telegram/webhook`, persists update IDs in Supabase/Postgres and replies through the Bot API. Real Telegram delivery remains blocked until the deployment owner supplies a bot token, HTTPS origin, webhook secret and database connection.
